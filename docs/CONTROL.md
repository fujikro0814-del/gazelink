# GazeLink 制御の定式化

実装前に式を定めるための文書。数値の既定値はすべて `core/config.ts` にある。記号の後ろの【】内は、対応する設定項目である。

## 1. 全体の構成

```
 手(マウス) ─ばね・ダンパ─ 主側仮想質量 ══ 通信路（遅延・損失）══ 結合PD ─ 従側仮想質量 ─ 環境（壁・床・箱）
   x_h          k_h, b_h        m_m, x_m   → (x_m, v_m, E) →        K_c, B_c     m_s, x_s        f_e
                                            ← (f_c, E)     ←
```

- **主側（クライアントで動く）**
  - 手の位置 x_h を、ばねとダンパで仮想質量 m_m につなぐ。
  - 通信路から返ってきた力 f_m がこの質量に加わる。
  - 仮想質量の位置が、画面の「指令のゴースト」になる。
- **従側（サーバまたは Worker で動く）**
  - 届いた指令から、指令点 x_d を作る。
  - 結合 PD で従側の質量 m_s を引く。
  - 結合の力 f_c を通信路へ返す。
- **自由度と刻み**
  - 並進 3 自由度を、軸ごとに独立に扱う（ベクトルで書く）。
  - 物理は 1 kHz の固定刻み（Δt = 1 ms【PHYSICS.dt】）。
  - 通信は 100 Hz（10 ms ごと）。受け取った値は、次の値が来るまで保持する（0 次ホールド）。

指示書は「なし」を「位置を送り、力を返す」としていた。ここでは三方式とも同じ構成（**位置と速度を送り、結合の力を返す**）にそろえ、違いは通信路の両端に入れる受動化の仕組みだけにする。こうすると比較が公平になる（実装前に合意済み）。

## 2. 物理モデル

### 2.1 主側

```
m_m ẍ_m = k_h (x_h − x_m) + b_h (ẋ_h − ẋ_m) + f_m
```

| 記号 | 意味 | 既定値 |
|---|---|---|
| m_m | 主側の仮想質量【MASTER.mass】 | 0.5 kg |
| k_h | 手とのばね【MASTER.handK】 | 300 N/m |
| b_h | 手とのダンパ【MASTER.handB】 | 60 N s/m |
| f_m | 通信路が主側に加える力 | 方式ごとに §3・§4 で決まる |

**b_h を大きくした理由（遅延余裕の見積もり）：**
- 壁に接触している間、従側は壁に押さえつけられている。このとき一巡の伝達関数は近似的に次の形になる。

```
L(s) = K_eff e^{−sT_rt} / (m_m s² + b_h s + k_h)
K_eff = K_c k_e / (K_c + k_e)      （結合ばねと壁の直列）
T_rt  = 往復遅延
```

- b_h = 8 のとき：主側の共振（√(k_h/m_m) ≈ 24 rad/s）でゲインが 1 を大きく超える。位相余裕が約 33° しかなく、往復わずか約 14 ms で不安定になる。これでは遅延 0 でも実ネットワークの遅延で発振してしまう。
- b_h = 60 のとき：ゲイン交差角周波数は約 7.7 rad/s、位相余裕は約 120° になる。遅延余裕は往復で約 270 ms、片道で約 135 ms である。
- したがって「なし」は、片道 0〜50 ms では安定し、200 ms 以上では発振する。これは指示書が求める見せ方と一致する。値は §8 の自動試験で確かめる。

### 2.2 従側

```
f_c = K_c (x_d − x_s) + B_c (v_d − v_s)                    （結合 PD）
m_s ẍ_s = f_c + f_e − (b_0 + b(t)) ẋ_s
```

| 記号 | 意味 | 既定値 |
|---|---|---|
| m_s | 従側の仮想質量【SLAVE.mass】 | 2 kg |
| K_c, B_c | 結合 PD【SLAVE.couplingK, couplingB】 | 600 N/m, 30 N s/m |
| b_0 | 常にかかる構造減衰【SLAVE.baseB】 | 2 N s/m |
| b(t) | 視線適応ダンピング（§5） | — |
| x_d, v_d | 指令点の位置と速度。v_d は常に (x_d(k) − x_d(k−1))/Δt と定義する | — |

### 2.3 環境（ペナルティ法）

侵入量 δ > 0 のときだけ、外向き法線 n の方向に次の力を出す（面を引き込む力は出さない）。

```
f_e = max(0, k_e δ − b_e (ẋ_s · n)) n
```

- 壁：k_e = 5000 N/m、b_e = 20 N s/m【ENV.wallK, wallB】。床と目標の箱も同じ形。
- 摩擦は扱わない。

### 2.4 時間積分

半陰的オイラー法を使う。

```
v(k+1) = v(k) + a(k) Δt
x(k+1) = x(k) + v(k+1) Δt
```

- 壁の固有角周波数は √(k_e/m_s) ≈ 50 rad/s である。ω Δt ≈ 0.05 と十分小さいので、数値的に安定である。
- **刻みの管理：** 実時間との差を貯め、`while (acc ≥ Δt) { step(); acc −= Δt; }` の形で必要な回数だけ刻む。
- 1 回の起床で貯まった分が 200 刻み【PHYSICS.maxCatchUpSteps】を超えたら、超えた分は捨てる（タブが裏に回って止まっていた場合）。
- 起床の周期と 1 回あたりの刻み数は、画面に表示する。

## 3. 通信路の端子とエネルギー

通信路を 2 端子対とみなす。**通信路へ入る向きの電力を正**とする。

| 端子 | 通信路が受け取る量 | 通信路が出す量 | 通信路へ入る電力 |
|---|---|---|---|
| 主側 | 速度 v_m | 力 f_m | P_M = −f_m · v_m |
| 従側 | 力 f_c | 速度 v_d | P_S = −f_c · v_d |

**確認：** 遅延なし・損失なしで x_d = x_m、f_m = −f_c のとき、P_M + P_S = f_c·v_m − f_c·v_m = 0 となり、通信路は何も生まない。

各端子で、流れの向きごとにエネルギーを分けて積算する（TDPA の基本）。

```
E_M^in(k)  = Σ max(0,  P_M) Δt      E_M^out(k) = Σ max(0, −P_M) Δt
E_S^in(k)  = Σ max(0,  P_S) Δt      E_S^out(k) = Σ max(0, −P_S) Δt
```

- 右向きの流れは、E_M^in として入り、E_S^out として出る。
- 左向きの流れは、E_S^in として入り、E_M^out として出る。

**通信路の受動性（Ryu, Artigas, Preusche 2010）：** 往路の遅延を D_f、復路の遅延を D_b とするとき、次の 2 つが成り立てば、通信路は受動的である（エネルギーを生まない）。

```
W_R(k) = E_M^in(k − D_f) − E_S^out(k) ≥ 0      （従側で監視）
W_L(k) = E_S^in(k − D_b) − E_M^out(k) ≥ 0      （主側で監視）
```

- E_M^in(k − D_f) は、`CMD.eIn` として実際に従側に届いた値そのものである。したがって遅延の大きさを知らなくても判定できる。
- 遅延が変動しても、損失があっても、同じように判定できる。届いた値は古いほど小さい（積算値は増える一方）ので、判定は常に安全側になる。

**通信路が生み出したエネルギー（表示・試験用）：**

```
E_gen = (E_S^out − E_M^in,rcvd) + (E_M^out,rcvd − E_S^in)
```

- 従側が知っている値だけで計算する。`STATE.eGen` として配信する。
- TDPA では各項が 0 以下に保たれるので、E_gen ≤ 0 となる。E_M^out,rcvd ≤ E_M^out(k) ≤ E_S^in,rcvd(主側で) ≤ E_S^in(k) だからである。
- E_gen > 0 は、通信路（遅延＋ホールド）がエネルギーを湧き出させたことを意味する。

**蓄積エネルギー（表示用）：**

```
H_m = ½ m_m |ẋ_m|² + ½ k_h |x_h − x_m|²
H_s = ½ m_s |ẋ_s|² + ½ K_c |x_d − x_s|² + ½ k_e δ²
```

## 4. 三つの方式

### 4.1 なし（素朴な双方向制御）

- **従側：** 届いた指令を 1 次ホールドで外挿した目標 `x̂ = x_m,rcvd + v_m,rcvd min(t_k − t_rcv, 1.5 T_c)` に、指令点を時定数 T_c（= 10 ms、通信周期）で追従させる。`v_d = v_m,rcvd + (x̂ − x_d)/T_c` とする。こうすると、新しい `CMD` が届いても指令点が飛ばず、結合ダンパに一瞬だけ大きな力が出ることがない。
- **主側：** f_m = −f_c,rcvd とする。
- エネルギーは §3 のとおり積算するが、何も制限しない。

### 4.2 TDPA（時間領域受動性の手法）

Ryu・Artigas・Preusche（2010）の構成に従う。従側と主側に、それぞれ受動性観測器（PO）と受動性制御器（PC）を置く。

**従側の PC**（アドミタンス型：通信路が速度を出す端子なので、直列の PC で速度を修正する）

各刻み k で次の順に計算する。

1. 結合の力を求める：`f_c(k) = K_c (x_d(k−1) − x_s(k)) + B_c (v_d(k−1) − v_s(k))`。前の刻みの指令点を使うので、この刻みでは入力として確定している。
2. 基準速度を求める：`v_ref = v_m,rcvd + v_drift`。
3. 観測値を求める：`W_R' = E_M^in,rcvd − E_S^out(k−1) − max(0, f_c·v_ref) Δt`
4. W_R' < 0 かつ |f_c| > ε のとき：
   - `β = −W_R' / (Δt |f_c|²)`、`v_d = v_ref − β f_c` とする。
   - このとき出ていく電力はちょうど W_R' 分だけ減り、W_R(k) = 0 になる。
   - 消したエネルギー β|f_c|² Δt を E_diss に積算する。
5. そうでなければ `v_d = v_ref` とする。
6. 指令点を更新する：`x_d(k) = x_d(k−1) + v_d Δt`。電力 P_S = −f_c · v_d を積算する。

**位置ずれ（drift）の補正：**
- PC が速度を削った分だけ、x_d は x_m から離れていく。
- そこで、観測器に余裕（W_R > 0）がある分だけ補正速度を足す。

```
v_drift = κ (x_m,rcvd − x_d(k−1))                         【TDPA.driftGain】κ = 4 1/s
ただし補正で余分に出るエネルギー max(0, f_c·v_drift) Δt が ρ W_R(k−1) を超えるなら、v_drift を縮める    【TDPA.driftBudget】ρ = 0.5
```

- この補正は上の手順 3〜4 の観測器を通るので、受動性は崩れない。

**主側の PC**（インピーダンス型：通信路が力を出す端子なので、並列の可変ダンパで力を修正する）

1. 力の基準値を `f_ref = −f_c,rcvd` とする。
2. 観測値を求める：`W_L' = E_S^in,rcvd − E_M^out(k−1) − max(0, f_ref·v_m) Δt`
3. W_L' < 0 かつ |v_m| > ε のとき：`α = −W_L' / (Δt |v_m|²)`、`f_m = f_ref − α v_m` とする。そうでなければ `f_m = f_ref` とする。
4. 電力 P_M = −f_m · v_m を積算する。

**方式の切り替えとエネルギーの積算：**

- 「なし」の間に通信路が生んだエネルギーが残ったまま TDPA に切り替えると、問題が起きる。観測器は、その不足分（例：250 J）を一度に取り戻そうとして、指令速度を逆向きに大きく振る。実機を模した確認では、数千 N の力の突出になった。
- そこで、方式の切り替えを**新しい試行番号（epoch）の始まり**として扱う。
  - サーバは epoch を進め、`EVENT{kind:"reset", data:{rebase:true}}` を送る。
  - 両端はエネルギーの積算値を 0 から数え直す。位置はそのままにする。
  - 古い epoch の `CMD`・`STATE` は両端で捨てる。
- 従側は、新しい epoch の最初の `CMD` が届くまで、最後の指令位置で待つ。その間、使ってよいエネルギーは 0 とする。
- 切り替えの時点で通信路の中にあるエネルギーは使わないので、安全側の扱いである。これは試験で確かめる（`tests/passivity.test.ts`）。

### 4.3 波変数（Niemeyer & Slotine）

特性インピーダンスを b_w【WAVE.impedance、制御盤で変更可】とする。軸ごとに次の式を使う。

**主側：**

```
F_m = b_w ẋ_m − √(2b_w) v_m,rcvd          （主側が通信路へ加える力、f_m = −F_m）
u_m = √(2b_w) ẋ_m − v_m,rcvd              （CMD.um で送る）
```

**従側：**

```
ẋ_sd = (√(2b_w) u_s,rcvd − f_c) / b_w      （指令速度、v_d = ẋ_sd）
v_s  = u_s,rcvd − √(2/b_w) f_c            （STATE.us で返す）
```

**性質：**
- 各端子の電力は ½(u² − v²) になる。一定の遅延なら、この通信路は遅延の大きさによらず受動的である。
- 一方で、次の 2 つが既知の短所として見える。
  - 自由空間でも b_w 相当の粘りを感じる。
  - 位置がずれていく。
- 位置ずれの補正は、TDPA と同じく観測器 W_R に余裕がある分だけ行う。
**標本化による受動性の破れと、その対策（段階 5 の模擬で確かめた）：**

- 波を 100 Hz で送り、受け側で次の値まで保持（0 次ホールド）すると、1 つの標本のエネルギー u²/2 を 10 刻みにわたって繰り返し使ってしまう。そのため、通信路がエネルギーを湧き出させる。
- 実際に、片道 50〜200 ms で数値が発散した。
- そこで次の 2 つを入れた。
  1. **送り側：** 1 通信周期ぶんの u（v）の**平均**を送る。平均の 2 乗は 2 乗の平均を超えない（Jensen の不等式）。したがって、平均を 1 周期保持して取り出すエネルギーは、送り側で入ったエネルギーを超えない。
  2. **受け側：** 1 つの標本は**最大 1 周期ぶん（10 刻み）だけ**使い、次の標本が来なければ 0 とする。損失や揺らぎで標本が遅れても、同じエネルギーを二度使わない。
- 対策後は、片道 0〜800 ms のすべてで発振しなかった。E_gen は正になりうるが、最大でも約 0.3 J にとどまった。E_gen はこの節の平均化・保持の前後ではなく、刻みごとの端子電力で測っているので、離散化の差が残る。

## 5. 視線適応ダンピング

### 5.1 視線点

- 画面上の推定点 (u, v) から、カメラの光線を 3D 空間へ飛ばす。
- 光線と作業空間の物体（壁・目標・通過点）または床との交点を、最初に当たったものとして求める。これを視線点 p_g とする。
- 推定の信頼度を c ∈ [0, 1] とする。

### 5.2 注意の場（指数減衰の重み付き積算）

時刻 t_i の視線標本 (p_i, c_i) について、次のように定める。

```
w_i(t) = c_i exp(−(t − t_i)/τ_f)                      【GAZE.forgetTau】τ_f = 2 s（制御盤で変更可）
K(p, p_i) = exp(−|p − p_i|² / (2σ²))                  【GAZE.sigma】σ = 8 cm（視線推定の誤差に合わせて広め）
A(p, t) = Σ_i w_i K(p, p_i) / (Σ_i w_i + ε)   ∈ [0, 1]
```

- A は「直近の注意のうち、どれだけが p の近くに向いていたか」を表す。
- 古い標本は、重みが exp(−5) 未満になった時点で捨てる【GAZE.historyHorizon】。
- 忘却のない単純な積算にはしていない。
- 床の熱分布表示は、A を格子上で評価して描く。

### 5.3 減衰係数の目標値（差し替え可能な一つの関数）

```
d_obs = 先端から壁までの距離
p_obs = clamp(1 − d_obs / r_obs, 0, 1)                      【GAZE.obstacleRange】r_obs = 8 cm
u     = clamp(w_a (1 − A(x_s)) + w_o p_obs, 0, 1)            【GAZE.wAttention, wObstacle】
b*    = B_MIN + (B_MAX − B_MIN) u                            【GAZE.bMin, bMax】2〜60 N s/m
```

- 注意が向いている場所（A ≈ 1）で、障害物から遠ければ、b* ≈ B_MIN（軽い）。
- 注意の外（A ≈ 0）や壁の近くでは、b* は B_MAX に近づく（重い）。
- この部分は `core/gaze/damping.ts` の `dampingLaw(history, tip, env, params, now)` 一つに閉じ込める。依頼者はこの関数だけを自分の方式に差し替えればよい。

### 5.4 信頼度の扱いとスルーレート制限（上の関数の外側）

```
ĉ ← ĉ + (1[c ≥ c_min] − ĉ) Δt / τ_c          【GAZE.minConfidence, lowConfTau】 c_min = 0.5, τ_c = 0.4 s
b_goal = ĉ b* + (1 − ĉ) b_mid                  b_mid = (B_MIN + B_MAX)/2
b(k)   = b(k−1) + clamp(b_goal − b(k−1), −S Δt, S Δt)       【GAZE.slewRate】S = 150 N s/m/s
```

- まばたきや顔が外れて信頼度が落ちると、b は中間値へなめらかに戻る。
- スルーレート制限の内部状態 b は、**試行の開始（RESET）と方式の切り替え（CTRLCFG）のたびに B_MIN へ初期化する**。前の条件の値を引き継ぐと、立ち上がりが不自然に遅れるためである。これは試験で確かめる（`tests/gaze.test.ts`）。
- 視線適応を OFF にしたときは、b = B_MIN で一定とする。

### 5.5 ダンパをかける場所（主側が標準）

b(t) は、従側（サーバ）で従側の先端位置・環境・視線の履歴から計算する。それをどこにかけるかは、制御盤で選べる【`CTRLCFG.gaze.target`】。

| 選択 | 運動方程式に加わる項 | b の届け方 |
|---|---|---|
| **主側（標準）** | 主側の質量に `−b(t) ẋ_m`（地面に対するダンパ） | `STATE.b` で主側へ届ける（下りの遅延ぶん遅れるが、b はスルーレート制限で変化が遅いので影響は小さい） |
| 従側 | 従側の先端に `−b(t) ẋ_s` | — |

**主側を標準にした理由**（段階 5 の模擬で確かめた）：

- **従側にかけて TDPA と組み合わせると、従側がほとんど動かなくなる。**
  - 従側のダンパは、通信路の従側端子から出たエネルギーを消費する。
  - TDPA は、そのエネルギーを主側から届いた分（E_M^in）の範囲に制限する。
  - その結果、b が大きい場面では指令点の速度が削られる。片道 100 ms、視線が遠くにあって b ≈ 55 N s/m のとき、主側と従側の位置ずれは約 13 cm になった。
  - 静止すると新たなエネルギーが入らないので、位置ずれの補正も進まない。
- **主側にかけるダンパは通信路の外にある**ので、TDPA のエネルギー収支を圧迫しない。
- **主側を重くすると、遅延に対する余裕も広がる**（§2.1 の b_h を実質的に増やすのと同じ）。
  - 例：片道 200 ms・方式「なし」で、視線適応 OFF では壁接触で発振する。ON では壁の近くで b が上がり、発振しない。
- 「従側」を選んだときに TDPA で位置ずれが大きくなる様子は、比較として見せる。

注意の強さ A は、指示書どおり**従側の先端位置**で評価する。

### 5.6 可変ダンピングが受動性を壊さないこと

かける場所（主側 ẋ_m・従側 ẋ_s）のどちらでも議論は同じなので、以下では従側で書く。主側にかけた場合は、ẋ_s を ẋ_m に、H_s を H_m に、P_S を P_M に読み替えればよい。可変ダンピングが出す電力は次のとおりである。

```
P_b(t) = −b(t) |ẋ_s|²
```

- 実装では b(t) を常に [B_MIN, B_MAX] に切り詰めている（B_MIN ≥ 0）。そのため、あらゆる時刻で P_b(t) ≤ 0 である。つまり、この要素はエネルギーを消すだけで、生むことはない。
- b の変化の速さや向きは P_b の符号に関係しない。
  - これは、ばねの剛性を変える場合とは違う。可変剛性では、½k(t)x² の変化から能動性が生じうる。
  - ダンパは蓄積要素を持たないので、スルーレート制限の有無にかかわらず受動的である。
- 従側の蓄積関数 H_s について、次が成り立つ。

```
dH_s/dt = −P_S − (b_0 + b(t))|ẋ_s|² − （壁のダンパ損失） ≤ −P_S
```

- よって、従側全体は通信路の従側端子から見て受動的である。
- 従側の TDPA が保証するのは「通信路が受動的である」ことだけである。したがって、系全体の受動性（受動要素どうしの結合は受動的）は、b(t) を入れても保たれる。
- 離散時間では、ダンピング力を刻みの頭の速度 v(k) で評価している。その 1 刻みの間に消えるエネルギーは b|v|²Δt + O(Δt²) である。b Δt / m_s ≤ 60·0.001/2 = 0.03 ≪ 1 なので、数値的な能動化（過剰な減衰で速度の符号が反転すること）も起きない。

## 6. 予測表示

- 最新の `STATE`（時刻 t_s、サーバの時計）の従側状態から出発する。そこへ、送信済みでまだ反映されていない `CMD`（seq > `STATE.cmdSeq`）を、推定した上りの片道遅延 T̂_up 後に届くものとして順に当てはめる。
- 従側と同じ運動方程式（§2.2・§2.3、方式は「なし」の補間）を、現在時刻 + T̂_up まで 1 kHz で進める。
- 求めた先端位置を逆運動学で関節角に直し、橙色の半透明アームとして描く。
- 実際のアーム（白）、予測アーム（橙）、指令のゴースト（水色）の三つを重ねて表示する。

## 7. 発振の検出

- 直近 1.0 秒の接触力の大きさ |f_e| を 200 Hz に間引き、平均を引く。そのうえで Hann 窓をかけ、2〜20 Hz の範囲を 0.5 Hz 刻みの離散フーリエ変換で調べる。Hann 窓は、接触し始めた瞬間の力の段差が低い周波数に漏れ出すのを抑えるためである。
- 最大の山の振幅を A_pk、平均を F̄ とする。次の 2 条件がどちらも成り立てば、「発振」と判定する。
  1. 窓の中に接触がある。
  2. 次のどちらかが成り立つ。
     - A_pk > max(2 N, 0.3 F̄) であり、かつ平均値を 6 回以上横切っている（3 周期ぶん）。横切りの判定には、幅 max(0.5 N, 0.25 A_pk) のヒステリシスをつける。段差や傾斜は平均値を 1 回しか横切らないので、これで除外できる。
     - 接触の開始・終了が 4 回以上ある（跳ね返り）。
- 判定したら、`EVENT{kind:"oscillation"}` と `STATE.status` のビット 1 で知らせる。
- 自動実験では、押し当て区間全体に同じ判定を行う。

## 8. 自動試験で確かめること（段階 5・6）

- 「なし」：片道 200 ms 以上で壁に押し当てると、発振と判定される。片道 0 ms では判定されない。
- 「TDPA」：同じ条件で、発振と判定されない。かつ、すべての時刻で E_gen ≤ 10⁻⁹ J（数値誤差の範囲）である。
- 視線適応：RESET と方式の切り替えで、スルーレート制限の状態が B_MIN に戻る。
